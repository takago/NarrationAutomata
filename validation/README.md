# リファイナー・品質検査・リデューサー

> 第7段階リファクタリング後の `validation/` パッケージについて説明します．

## モジュール構成

| ファイル | 役割 |
| --- | --- |
| `ui.py` | 「リファイナー」タブの検査・編集UI，処理の開始・表示更新 |
| `core.py` | ルール検査，LLM個別・全体検査，修正候補の生成と検証 |
| `refine_job.py` | リファイナーの実行登録，状態JSONの読み書き |
| `store.py` | 検査結果，履歴，ログの保存 |
| `time_ui.py` | リデューサーと新しいプロジェクトへの生成引き継ぎ |

## 手動の品質検査

品質検査ではルール，LLMによるスライド別検査，LLMによる全体検査を選び，順次実行できます．開始時には前回の検査結果を置き換えます．進捗はサイドバーとタブ内に表示され，指摘はスライドごとにまとめられます．検査中は結果閲覧が中心になり，中断時は取得済みの結果を確認できます．

検査終了後に，「再生成」「自動校正」「手動編集」で候補を作成します．差分比較の基準は検査で問題が発見された時点の原稿です．編集欄への反映と，原稿ファイルへの保存は別操作です．保存した場合にのみ原稿を更新し，必要な下流生成物を無効化します．問題一覧から解決済みのスライドを取り除きます．

## 自動リファイナー

設定により全自動生成の処理に含めることができます．選択した検査をルール→LLM個別→LLM全体の順に行い，指摘があれば自動校正と出力検証を実施します．修正後には必要に応じて確認検査を行い，エラーや未解決項目は手動確認用として残します．**自動実行は1回限り**であり，繰り返し回数の設定はありません．必要ならユーザーが手動で再実行します．

結果には対象スライド，理由，修正の成否，修正前後の差分が含まれます．内容リファイナーの状態は `content_job.json`，検査結果は `validation/results.json` などに保存されます．「統計」タブは実行負荷の分析用であり，修正結果の確認先ではありません．

## リデューサー

`time_ui.py` が，目標時間に合わせた原稿短縮と新規プロジェクト作成を担当します．チェックボックスがONの場合のみ，原稿調整後に `app.py` が②〜④の生成を引き継ぎます．デフォルトはOFFです．時間調整の結果は単回実行の `result` フィールドに保存します．旧形式の `rounds` 配列には対応しません．

リデューサータブで，原稿の変更内容，目標時間，生成結果を確認します．中断・例外・再接続時には，原稿短縮と動画生成のどちらの工程かを区別して判断してください．

## ジョブ管理・再接続

通常生成とリファイナーは `JobManager` の排他制御を共有します．ジョブの実行実体，状態ファイル，ブラウザ表示は別々に管理されています．リファイナーの実行登録は `refine_job.py` が担当します．画面を閉じてもサーバでの作業が継続する設計ですが，サーバプロセスが停止した場合の自動復旧までは保証しません．

## テストと保守

```bash
python3 -m unittest discover -s tests -v
```

単体テストに加え，手動検査・自動校正・中断，通常生成からの切替，時間調整から②〜④への引き継ぎを実機で検証してください．検査・校正プロンプトは `core.py` にあり，ドキュメント整備のために変更・短縮しないでください．旧バージョンの保存データや旧実行回数形式の互換性は保証しません．

## ユーザによる追加指示

リファイナータブで改善方針を自由記述できます．プロジェクトの `validation/settings.json` に保存され，検査結果の初期化後も維持されます．手動のスライド別・全体LLM検査に指示を参考情報として渡し，妥当性を確認してから指摘に採用します．自動校正は従来の指摘・差分確認を利用します．自動リファイナーの実行条件は変更しません．
